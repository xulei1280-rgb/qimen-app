## 1. 审核结论与范围

现有 `luck-outlook-20261009.1` 已提供大运双重比较、年度综合与年度增量，但它是工程参考模型。程序能够复算、界面状态一致，不等于岁运判断符合全部原典条件，更不等于现实预测已经验证。

本次直接核对 `bazi-engine.js` 中的 `evaluateLuckOutlook`、`compareOutlookContexts`、`outlookElements`、`buildTemporalPatternContext`、`strengthScore`、`carryingCapacityFeedback`，并检查页面调用与对应检查脚本的用途。对底层格局、喜用、合冲算法仅检查直接接口与依赖，未完成这些模块的全部规则审计；下文相关项标明这一边界。

用户确认的目标是判断大运对原局的好坏，以及较上一运的升降。四类结构是首批核验案例，不限制适用命局；需要覆盖会影响大运方向的原局需求、岁运作用、有效性与成败救应。范围按是否直接影响这个判断收敛，原有流年需求保持已有定义，不借此扩展新功能。

主要待改项：

1. 状态等级变化会直接产生方向证据，尚未在比较层明确完成成格而不喜、变格而不忌的例外裁决。
2. 病点按类别消失会被视为改善，不能排除主线变更、改名或不再适用导致的消失。
3. 有效喜忌仍按原局五行清单汇总，不能完整表达同一五行在不同作用对象上的相反效果。
4. 年度权重、承载阈值和喜忌容差有工程参数依赖；当前没有证明这些数值可作为吉凶裁决标准。
5. 比较层把部分喜忌反向作用放入保留因素，但仍需判断这些作用是否足以破坏主要路径；未知情况不能提前降权。
6. 当前待判覆盖输入缺失与月令未定，结构不可比、关键反证未定等情况仍需补充。

这些是代码与目标方法之间的缺口，不表示已证明所有显示结果错误。本轮不伪造具体命例的现实吉凶答案。

## 2. 固定的产品含义

| 显示项 | 参照对象 | 所回答的问题 |
| --- | --- | --- |
| 本运对原局：助益／持平／受阻 | 原局 → 原局＋本运 | 本运是否改善原局关键发挥条件 |
| 较上一运：上升／持平／下降 | 原局＋上一运 → 原局＋本运 | 相对时间上的上一柱，哪些关键条件变好或变差 |
| 年度综合：偏吉／平／偏凶 | 原局 → 原局＋本运＋流年 | 在本运背景下，这一年完整条件相对原局如何 |
| 对本运：改善／维持／拖累 | 原局＋本运 → 原局＋本运＋流年 | 流年怎样改变本运已经形成的条件 |

重要利弊同时成立、经救应后仍不能归一时，本运对原局、较上一运及年度对本运用「利弊并存」，年度综合用「吉凶并见」。这是已确认的利弊并存；决定方向的关键依据无法确认时用「待判」。第一柱大运没有上一柱，不输出升降方向。

上述四项参照关系和升降标签属于产品定义，不是原典直接给出的统一计算公式。「年度净变化」不是把运、年分数相加；「相对上一运」也不是用上一运标签与本运标签相减。

原局结论固定保存；阶段作用环境可以改变当前结构与喜忌的实际功能，但不得倒写出生原局。不同大运分别从同一原局评估，不累积上一运影响。

生活解释限于命理判断对应的学习支持、工作职责、表达产出、资源协调等条件倾向。没有具体领域作用依据时只解释发挥条件，不自动推断收入、晋升、婚变、疾病或其他事件。

## 3. 采用方法与术语

沿用项目已有 [子平规则交叉索引](../codex/modules/pattern-sources/rule-crosswalk.md)：

- 主线：《子平真诠》的月令取格、相神、成败救应与行运条件。
- 补充：《三命通会》对应格局及岁运篇；使用与主线相容的条件，冲突保留异说，不以书目数量投票。
- 校正：《滴天髓》及《滴天髓阐微》的轻重、冲战、通关、真假与气候条件。明确区分原文、原注、任氏评注。
- 调候：《穷通宝鉴》只校正明确的寒暖燥湿问题，不独立承担整体升降裁决。
- 神煞、纳音等不独立决定这四项标签。

术语分开：格局用神是月令立格体系中的取用对象；相神是辅助格局成立的关键因素；扶抑喜用是帮助平衡、承载的因素。它们可能重合，也可能发生冲突，不能全部简化为同一个「喜水／忌火」清单。

本提案默认大运干支十年合看，并核对干支互相支持或制约；不机械前五年只看天干、后五年只看地支。这采用任氏岁运评注的解释，属于明确的体系选择，不宣称所有流派一致。年度也同时看天干地支，不将传统的干支侧重转换为统一数值比例。

## 6. 方向归纳方法

以下是拟采用的工程归纳，不冒充原典逐字算法。

1. 以原局关键需求与作用链为起点，例如需要印护官、需要食制杀、需要日主任财；阶段确有成格或变格时，复核阶段正在使用的路径，并说明它解决了什么、损失了什么。辅助因素只有影响原局需求或阶段有效路径时才能承担整体方向判断，不能用原局喜忌清单否决所有新路径。
2. 在阶段环境核对新增、受损、失效、救应与转移；每条证据必须指明作用对象与路径。状态名变化只是调查入口。
3. 同一因果链先判制化结果：已经有效解除的破点不再作为仍然生效的不利作用；救应造成的新破点也不能漏掉。
4. 关键反证未核清、唯一方向来自未经核实的数值跨阈值，或关键结构转移后不可比时，判待判。辅助且不影响方向的未定项可保留说明，不必使所有结论待判。
5. 已确认主要改善，且关键不利作用已排除或有效化解，归纳为助益／上升／偏吉／改善；主要恶化同理。
6. 独立的重要有利、不利路径都仍有效、无法统一时，输出利弊并存／吉凶并见；不得用数量投票、总分抵消或任意权重决定谁胜。
7. 主要条件已核对且没有明显方向变化，才输出持平／平／维持；条件相同也不表示现实生活不会变化。

“结构优先”表示先查关键路径，不表示把任何反向喜忌作用自动放到低层。结构优先与力量、根气、调候相互校正；若力量或气候已经影响关键路径，它就是主要条件的一部分。

四项比较各自应用上述方法。因此「本运受阻，但较上一运上升」和「年度综合偏凶，但对本运改善」均可成立，需要分别显示参照对象。

### 11.3 首批必要修正

1. **官印：区分印的实际用途。** 阶段证据区分普通佩印、制伤护官、承接重官扶身；复用现有病药结算。已解之病不因「成而有瑕」排名重复扣方向，财与食伤也不按格名一律判坏。
2. **食杀：补足轻重与作用对象分支。** 在阶段判断中区分助食、助杀、助身；印夺食与印扶身分开，财生杀与财制枭分开。复用已有枭夺食与财制枭逻辑，不另建一套破格系统。
3. **伤印：候选与有效配印分开。** 不把「印透」直接当成「根深、足以制伤」；判断伤、身、印的相对条件及印是否过度。候选可保留，但不足以单独贡献正向证据；不规定身强一律坏、财一律坏。
4. **财弱：区别扶身与分财。** 阶段判断核对比印是否改善任财、是否同时发生有效分财，以及改善后是否仍需扶身。不仅凭「有比劫」设破点，也不因承载布尔值变好就宣布全部破点已解。

这里的「有效」最少要有：作用对象明确，参与干支可用，根气／得令与透藏资料支持该作用，位置或既有互动证据能支持路径，并已检查该路径上的破坏和救应。「关键」在本节指会影响这四类路径成立、破坏或恢复的条件；完整判断还包括第 12 节其他适用路径，不把任意十神变化升为整体方向。优先复用现有资料，不新增统一力度分值或任意食杀比例。

这些条件支持到哪一步，证据就说明到哪一步。关键轻重或救应未能确认且会改变方向时待判；已确认两条重要路径相反且无法归一时利弊并存；辅助未定项不阻止其余已确认结论。对两运及年度使用同一组条件、分别说明参照对象。

后续代码改动以完成大运好坏与相对升降判断为范围，不限于上述四类结构；特殊格、力量或气候等条件确实影响所判命局方向时，纳入对应核对。沿用项目既有体系和接口，不顺带增加经历录入、界面重做、外部引擎或全系统重构。若确需改共享格局函数，必须明确指出现有局部缺陷与受影响调用，不在岁运层复制另一套原局算法。

## 12. 完整核心判断规范

本节补全项目既定子平体系内的大运方向判断：覆盖适用主线、实际作用、成败救应、力量与气候校正，以及相对上一运的比较。「完整」指核心判断环节与适用路线不遗漏，不表示穷尽所有流派或把所有古籍断语列入程序。第 5 节的 `LK-*` 原则继续适用；以下条件与归纳是有来源的工程规范，本地实现与检查见第 13 节，用户已授权提交推送。

### 12.1 每柱大运的判断顺序

| 顺序 | 必须完成的判断 | 应留下的结果 |
| --- | --- | --- |
| 1 原局参照 | 读取已确认的四柱、出生月令、日主根气、主线、相神、破点和救应；区分正式成立与候选线索 | 原局实际需求、成立依据与影响方向的未定项；不因缺某五行就认定需补 |
| 2 适用路线 | 严格成立的从、化、专旺按自身语境；其余按月令常格及有效路径；近似特殊格不强行替代常格 | 适用分支与选择原因。两条路线会得出相反方向且无法确认时待判 |
| 3 运干、运支分别作用 | 分别检查运干、运支及藏干如何生、克、泄、耗、扶助原局对象；再检查运干与运支互相支持、制约 | 作用对象、直接作用、补根或损根、透清或受绊；不能把同五行干支当成同一种作用 |

| 8 对上一运归纳 | 上一运与本运分别从同一原局计算，再比较有效路径、残病、承载与关键气候条件 | 上升／持平／下降／利弊并存／待判；第一运注明无上一运 |

出生月令与原局身份固定，大运地支不替代出生月令。运中透出原有藏干、成局或救应可以改变阶段的实际路径，阶段判断也不要求把所有格局缺项都补齐才允许判断某个已确认作用。

### 12.3 作用有效性、力量与干支关系

每条会决定方向的作用按下表确认；判断状态区分「成立／不成立／未确认／不适用」。不成立可排除该作用，未确认不能当作不存在；不适用必须有与当前路线对应的理由。

| 条件 | 必须检查的证据 | 不能代替该证据的线索 |
| --- | --- | --- |
| 存在与用途 | 具体干支、藏干、十神及作用对象；它在此阶段负责生、制、化、护、泄还是破坏 | 五行名称、十神名称、格名本身 |
| 可用 | 透藏、得令、通根、生扶与受制；合绊、争合、损根后是否仍能发挥 | 「透干」不等于根深有力，「藏有」不等于立即独立发用 |
| 足以作用 | 按所用分支核对双方根气、令气、支持、泄耗及制化；说明不足、相称或过度的依据 | 固定根力比、十神个数、单一强弱档、`godForce` 布尔值或数值刚跨阈值 |
| 路径可达 | 原局位置、对应关系、既有生克或合冲通路；说明是否有阻隔与竞争作用 | 原局任意两神同时存在；把运柱固定当作与所有柱等距、同强度作用 |
| 结果持续有效 | 救应自身可用，作用确实改变目标，反证已检查，残余与新病已记录 | 药神出现、病名消失、格局状态提升本身 |

力量服务于具体任务：制杀看杀、食与日主承泄的关系；任财看财食压力与日主生扶根气；印化杀看印能否承接杀而生身。不能只有一个「日主强／弱」结论，却据此判所有任务都能或都不能。

**程序条件的对应方式。** 复用 `buildTemporalPatternContext` 当前阶段的数据，原局、上一运、本运均按相同口径读取；不直接以通用布尔值替代具体任务。下表是实现约定，不是新增原典公式。

| 待确认条件 | 现有数据与读取要求 | 对分支的约束 |
| --- | --- | --- |
| 主线与所用对象 | `monthCommand`、常格 `checks`、组合／特殊格成立证据及 `patternDisease`；核对每项检查的具体依据 | 格名或检查 `active` 本身不足以选取轻重分支；只接受有对应对象和作用条件的依据 |

| 相对轻重 | 将双方可用根气、得令、生扶与制泄耗按同一任务并列核对；有作用链成立证据时一并使用 | 不新增统一分值或任意根力比。双方依据交叉、无法确认谁占优时记未确认；不能把两边数值接近直接称为相称 |

分支选取采用保守的工程约定：只有根气、得令、实际生扶与制泄耗等独立条件共同支持相同轻重关系，且没有未核清的相反关键条件时，才确认相对偏重／偏轻；单一数量、强弱档或门槛变化不能完成确认。具体任务还要同时满足下表条件，不能只凭轻重关系输出整运方向。

| 所用分支 | 程序必须同时确认的条件 |
| --- | --- |
| 食制杀、刃杀平衡 | 食／刃与杀的相对关系已确认，制或相抗的路径可用；助食、助杀不会破坏实际所用对象。两方作用匹配还须有有效制化、无未解过制或杀压证据，并单独核对日主承泄任杀，不能以两方都出现称为相称 |
| 任财、食伤生财 | 财食作用链和压力对象已确认，日主根气、生扶及任财／承泄条件可核对。已有具体任用不足且无充分救应时才能选择助身；有效任用已成立而财食出口不足时才能选择助财食 |
| 伤官配印、印重取泄或财调节 | 制伤、扶身、泄秀或调印的任务明确；印的可用根、伤官实际作用、日主受生承泄分别有据。印增加后究竟补不足还是阻断出口要有具体后果，不能因印多或身强单项判过度 |
| 化神及其他特殊路线 | 既有资格检查明确，按化神或所从对象核对实际不足、过度与可用出口；不把常格日主强弱开关直接用于特殊路线 |

缺失的关键数据或无法核实的作用不能由程序补造。只把受影响的条件记未确认，再按第 12.5 节检查它是否会改变最终方向；已经确认的其他路径仍可使用。实现时将分支对应的输入、成立条件和反例写在同一规则旁，并据此验证，不以当前输出反推期望答案。

运干、运支同五行仍须分开记录：干可直接生克、参与五合，支可补根、冲根、成局并以藏干承接；运中透清原有藏干或会局发用须有具体证据。盖头、截脚只表示内部制约，必须检查原局是否有制约、通关与承接，不固定减半，也不自动判整运受阻。依据 S4、S9 干支有别与逢运透清。

合、冲、会局按「先核关系是否有效，再判影响对象」处理：合住关键相神与合去破点方向可相反；合而不化不按化后五行计算；会局不只检查字齐，还须检查成势、参与支是否可用及外冲；冲损关键根与冲去实际破点分开。合冲并见不静默抵消，墓库被冲不一律视为开库得利。刑害破、伏吟、反吟、岁运并临等名称都不独立产生整体方向，只有经确认影响关键路径的实际作用进入结算。沿用 S7 既有关系规则，具体异说未核清时保留说明。

寒暖燥湿只在偏性明确且影响当前用神或路径时参与主要裁决：改善过寒／过燥须有可用调节因素，继续加重或调节过度须检查反证；不能按出生季节自动喜某运，也不能用「金水伤官喜官」豁免所有伤官克官的结构。若气候改善同时破坏有效主链，两条路径都核实后按混合结果处理。依据 S9 气候得失，以及本地《滴天髓阐微》寒暖第 4703 行、燥湿第 4791 行的原文、原注与任氏评注。

### 12.4 成败救应与阶段转移

同一病点按「对象＋破坏机制＋所伤路径」追踪，不只按病名或类别匹配。有效救应可使病点化解，致病条件确实消失可使病点消除，两者都有明确因果依据时才支持缓解；只有病名缺项不足以确认。先结算实际作用，再区分已解、部分缓解、仍未解；相同病因在状态、喜忌、承载中重复出现，只保留一条主因及其后果，不重复投票或扣方向。

| 阶段变化 | 方向证据如何处理 |
| --- | --- |
| 新增关键相神、补足承载或接通原有出口 | 成立且未引入未解关键破坏时可作改善；只见候选或数量增多不足以成立 |
| 关键用、相神失用或残病加重 | 确认无有效救应或仍有残余时作恶化；有药先结算药的实际效果 |
| 旧病不再列出 | 明确制化或其致病条件消失才算缓解；因路径更名、换主线、资料未覆盖而缺项不自动改善 |
| 另一路径成立、原路径改变 | 列出新路的任用条件、所解决需求及原路损失；新格名不自动好，原格名改变不自动坏 |
| 特殊资格失去或恢复 | 复核阶段实际顺逆、出口与救应；可用常格路径不能遗漏，未能建立可靠参照则待判 |

### 12.5 好坏与相对升降的归纳

「关键」指对适用路径的成立、破坏、恢复或实际任用有决定作用的条件：须指出依赖对象及缺少它会导致什么，不按所有十神一律重要，也不按格局潜力等级决定重要性。「方向变化」须有条件变化与作用后果，不能只是分数、格名或状态名变化。

裁决顺序固定为：先结算有效作用、救应及致病条件消失，去除重复原因；再检查未确认条件在不同可行解释下是否会改变最终结论，会改变则待判，不会改变则保留说明；随后判断是否有独立关键利弊仍并存，再判断单一改善／恶化；主要条件已核对且延续时才持平。下表是归纳结果，不按行顺序直接匹配；关键救应未定且可能将混合变为单一方向时，待判优先于利弊并存。

| 比较后确认的情况 | 本运对原局 | 较上一运 |
| --- | --- | --- |
| 关键不足得到补足、残病减轻或有效出口改善；关键不利作用已排除／化解 | 助益 | 上升 |
| 关键路径受损、需求更难满足或残病加重；无足够有效救应 | 受阻 | 下降 |
| 适用路径及关键需求、反证已核对，实际条件大体延续；没有足以改变方向的有效作用 | 持平 | 持平 |
| 独立关键改善与恶化均成立，救应后仍并存、不能归一 | 利弊并存 | 利弊并存 |
| 决定方向的适用路线、作用有效性、轻重或救应未确认；或阶段转移无法建立共同参照 | 待判 | 待判 |

有弱线索不等于关键利弊并存；已经被排除的不利作用也不占一个不利票。辅助未定项可说明，不必使整运待判。若未确认项在不同可行解释下均不改变最终方向，可给出方向并保留该项；否则待判并指出缺哪项依据。已确认中性也必须说明核对了哪些主要条件，不能把空证据数组当成持平。

两运比较用同一原局需求逐项对齐，分别记录路径可用性、残病、承载和实际起作用的气候条件。原局已好而本运维持，可对原局持平；上一运曾损坏该路径而本运恢复，仍可较上一运上升。两运同为助益、同为受阻或同一格局状态，也不能据同标签直接判平；结构转移只有能说明共同任用条件的改善或恶化时才输出升降，否则保留混合或待判。

每项确定方向至少对应一条完整理由：原来需要什么 → 运中哪个实际作用改变它 → 有效性依据 → 反证与救应结果 → 得出什么方向。证据沿用现有返回结构补足规则与来源定位；内部复核能查到参与干支、作用对象和关键未定项，生活解释仍遵守第 2 节，不新增事件预测字段或界面功能。

### 12.6 与流年的关系及验证完成边界

大运结论先在原局＋本运环境独立得出，不用选中某个好／坏流年反向定义整柱大运。流年加入后重新核对年与原局、年与运以及改变后的实际路径，继续使用本节相同的有效性和救应规则；年度综合及年度对本运的变化保持第 2 节已有参照。一个年度结论不代表整运十年相同，也不把十年逐年标签多数投票成大运结论。本轮不增加应期、流月或流日规则。

后续实现的针对性验证必须覆盖：

- 八类常格主线各至少一组成立条件与反例／救应；表中会改变方向的不同所用分支均有对应检查，不能用八个代表盘宣称所有分支已验收。
- 项目已登记从、化、专旺路线的顺势有效、有效破坏，以及资格变化但存在其他可用路径／无法确认的情况。
- 同一五行的干与支不同作用、透清与藏而未用、合绊与合化、冲损所用与冲去破点、盖头截脚有无制化、承载或气候的改善与过度。
- 同一病只结算一次，已解与缺项不同；成格但受损、变格但可用；混合与待判不同；对原局与对上一运结论不同但各自有依据；年度独立改变条件。

这些是持续适用的覆盖要求，具体已运行检查见第 13 节；第 11.2 节八项仍属于实施前诊断。测试不以真实人物经历生成期望吉凶，不以穷尽全部古籍、全部命盘或新增验证平台为前置要求。
